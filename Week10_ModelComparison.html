Likelihood ratio tests, AIC, and regularization

How do we compare models that differ in complexity? This part covers the most rigorous test (predicting new data), two shortcuts that need only one fit (the likelihood ratio test and AIC), and regularization, which keeps every covariate in a single model and shrinks the coefficients toward 0.

1. Big picture

The FIT step gives estimates and their uncertainty for one model at a time. COMPARE weighs models against each other. It has three parts:

  1. Does the model fit the data at all?
  2. Does it beat its rivals, including a null model, and predict new data?
  3. Is it relevant to the problem we started with? (A judgment, not a statistic.)

Here we focus on part 2, comparing models fit to the same data. This includes:

  • Null-model tests: is there evidence that a model (a theory) outperforms an uninteresting one?
  • Model selection: which of several alternative models is best supported by the data?
  • Multimodel inference: when several models have some support, base predictions and inferences on all of them.

Adding parameters always improves the fit to the data in hand (see the WOD), so in-sample fit can't answer these questions. The most rigorous test is how well a model predicts new data from the same process:

  • Validation: fit the model to one data set and score its predictions on data it never saw, ideally collected separately.
  • Cross-validation: without new data, hold out part of the data, fit to the rest, score the held-out part, and rotate. This means fitting the model many times. (More on this later in the course.)

Because cross-validation takes many refits, we often rely on shortcuts that use a single fit to all the data:

  • LRT: does a bigger (nested) model fit better than chance alone would explain?
  • AIC: estimates how well a model would predict new data. In large samples it ranks models about the same way leave-one-out cross-validation does.

Ridge regression and the lasso take a third route: fit one large model and penalize the size of its coefficients, usually choosing the penalty strength by cross-validation.

Models that pass these tests are corroborated, not proven.

2. WOD: bias-variance tradeoff

The WOD (a short warm-up exercise at the start of class) gave seven measurements of seedling height and soil moisture, and two models: a straight line and a curve through every point. Both models were used to predict height at 19% moisture, where there were no data.

  • Sum of squared residuals: line 35.2, curve 0.
  • The new plot measured 14 cm. The line predicted 14.3; this curve predicted 11.2.

A perfect fit to seven points says little about prediction. Suppose we repeated the study many times with new seedlings from the same process, refitting both models each time:

  • A very flexible model fits the noise along with the signal. Its predictions are about right on average (low bias) but swing widely from one sample to the next (high variance).
  • A very simple model, such as a constant mean height, gives nearly the same prediction from every sample, but it misses a real trend, so it is consistently wrong (high bias, low variance).

Prediction error on new data includes both. More complexity lowers bias but raises variance, so the best predictive model lies somewhere between the extremes.

In the figure below, the study is repeated 20 times. Each sample uses the WOD's moisture values, with heights simulated from the red line plus random noise.

Both models center near the true height at 19% (red line), but the curve's predictions vary more than twice as much (SD 2.9 cm vs. 1.2 cm for the line).

3. Likelihood ratio test

Bolker's balsam fir data (section 6.6): cone counts on 242 trees, some at "wave" sites (where stands regenerate in waves) and some not. Model: \(\text{cones} \sim \text{NegBin}(\mu = a\,\text{DBH}^b, k)\). Do wave sites differ?

  • Full model: separate \(a\), \(b\), \(k\) for wave and non-wave sites (6 parameters).
  • Reduced model: one \(a\), \(b\), \(k\) for all trees (3 parameters).

The likelihood ratio test is the oldest shortcut. It applies to nested models, where the reduced model is the full model with some parameters fixed (often at 0). Here the reduced model fixes three: wave and non-wave sites share \(a\), \(b\), and \(k\).

Since the full model always fits at least as well, the real question is whether it fits better than extra parameters fitting pure noise would. If the reduced model is true, then in large samples the deviance

\[D = 2(\text{NLL}_{\text{reduced}} - \text{NLL}_{\text{full}})\]

follows a \(\chi^2_r\) distribution, where \(r\) is the number of fixed parameters (Wilks' theorem).

The test:

  1. Fit both models by maximum likelihood and record each minimum NLL.
  2. Compute \(D\). It is never negative, since the full model fits at least as well.
  3. Compare \(D\) with the 95% quantile of \(\chi^2_r\) (qchisq(0.95, r)).
  4. If \(D\) exceeds it (\(p < 0.05\)), the extra parameters improve the fit more than fitting noise usually would: evidence for the full model. Otherwise keep the reduced model, following the principle of parsimony.

The 1.92 cutoff for likelihood-based confidence intervals comes from the same result with \(r = 1\): \(\chi^2_1\)'s 95% quantile is 3.84, and \(3.84/2 = 1.92\) on the NLL scale.

library(emdbook)

4. AIC

\[\text{AIC} = -2\log\mathcal{L}(\hat\theta) + 2k\]

AIC can rank any set of models fit to the same response data, nested or not. The \(2k\) term estimates how much the in-sample fit overstates the fit to new data (the problem in the WOD). The AIC penalty handout shows where it comes from.

  • \(\Delta_i = \text{AIC}_i - \text{AIC}_{\min}\)
  • Akaike weights: \(w_i = e^{-\Delta_i/2} / \sum_j e^{-\Delta_j/2}\)
  • AICc adds a small-sample correction; BIC uses \(k \log n\) in place of \(2k\) (a harsher penalty).
# two intermediate models: wave changes only a and k (5 parameters), or only b (4)
nll_constb <- function(p) nll_nb(p[1:2][wave], p[3], p[4:5][wave])
nll_constak <- function(p) nll_nb(p[1], p[2:3][wave], p[4])
fit_constb <- fit_model(nll_constb, c(1, 1, 2, 1, 1))
fit_constak <- fit_model(nll_constak, c(1, 2, 2, 1))

fits <- list(full = fit_full, const_b = fit_constb, const_ak = fit_constak,
             no_wave = fit_nowave, poisson = fit_pois)
n <- nrow(fir)
aic_tab <- data.frame(model = names(fits),
                      k = sapply(fits, function(f) length(f$par)),
                      logLik = sapply(fits, function(f) -f$value))     # log L = -NLL
aic_tab$AIC <- -2 * aic_tab$logLik + 2 * aic_tab$k              # -2 log L + 2k
aic_tab$dAIC <- aic_tab$AIC - min(aic_tab$AIC)
aic_tab$weight <- exp(-aic_tab$dAIC / 2) / sum(exp(-aic_tab$dAIC / 2))
aic_tab$AICc <- aic_tab$AIC + 2 * aic_tab$k * (aic_tab$k + 1) / (n - aic_tab$k - 1)
aic_tab$BIC <- -2 * aic_tab$logLik + log(n) * aic_tab$k         # -2 log L + k log(n)
aic_tab <- aic_tab[order(aic_tab$AIC), ]
rownames(aic_tab) <- NULL

Question: The no-wave model has weight 0.52. Is there a 52% chance it's the true model?

Look at const_ak. It has one more parameter than the no-wave model and a log likelihood only 0.26 higher, yet it is just 1.48 AIC units behind. A useless parameter costs at most 2 AIC units, so being within 2 of the best model isn't evidence of support (Arnold 2010, J. Wildl. Manage. 74: 1175-1178).

5. Regularization: ridge and LASSO

Example: brown creepers. Counts at 50 point-count stations, with 10 standardized habitat covariates. These data are simulated, so we know the truth: only big trees, snags, and road distance matter.

Ten covariates give \(2^{10} = 1024\) possible subsets. Instead of searching them all, we can keep all 10 and penalize the size of the coefficients:

\[\text{ridge: } \text{NLL}(\beta) + \lambda\sum_j \beta_j^2 \qquad\qquad \text{lasso: } \text{NLL}(\beta) + \lambda\sum_j |\beta_j|\]

AIC charges for each parameter; these penalties grow with the size of the coefficients. One \(\lambda\) applies to every coefficient, so the covariates are standardized first. The lasso penalty has a corner at 0 that can set coefficients to exactly 0 (try the slider in Prices and budgets).

A penalty also makes the search simpler. Instead of comparing 1024 unordered models, we turn one dial: as \(\lambda\) falls from large to 0, the fit moves from the intercept alone to the full MLE, and cross-validation only has to choose a point along that path. The path passes through only a few of the 1024 subsets, in an order set by the data, so it can miss the best one. In exchange, its estimates are shrunk, and tuning one number overfits the held-out data less than picking a winner from a thousand models.

library(MASS)

Prices, budgets, and cross-validation

These tools come up in a lab on Bd infection in frogs, which fits a logistic model to a 60-pond survey with 8 pond features (data). This part offers another way to picture regularization, as a price or a budget for coefficient size, along with tips for glmnet and an outline of how cross-validation picks the penalty.

Prices and budgets

Think of fitting a model as shopping, with fit as the currency (measured in NLL units). Coefficient size buys a lower NLL: the first bit of a useful coefficient buys a lot, and later bits buy less. A penalty restrains the spending in one of two equivalent ways.

A price. The penalized form, which is what glmnet computes:

\[\min_\beta \; \text{NLL}(\beta) + \lambda \cdot \text{size}(\beta), \qquad \text{size} = \sum_j \beta_j^2 \text{ (ridge) or } \sum_j |\beta_j| \text{ (lasso)}\]

  • \(\lambda\) is the price of coefficient size, paid in NLL units.
  • There is no spending limit. The fit keeps adding size as long as the next unit lowers the NLL by more than it costs, and stops where the two balance.
  • How much gets spent depends on the data: if the fit improves steeply, it pays for a lot of size even at a high price.
  • At \(\lambda = 0\), size is free and we get the MLE.

A budget. The constrained form:

\[\min_\beta \; \text{NLL}(\beta) \quad \text{subject to} \quad \sum_j \beta_j^2 \le t^2 \text{ (ridge) or } \sum_j |\beta_j| \le t \text{ (lasso)}\]

  • \(t\) is a fixed allowance of coefficient size, with no price. The fit spends it wherever it lowers the NLL most.
  • If the MLE fits within the allowance, the limit doesn't bind and we get the MLE. Any \(t\) at least as large as the MLE's size acts like an unlimited budget.

The bridge. Every price has a matching budget that gives the same coefficients.

  • Fix \(\lambda\), fit, and add up the size of what was bought. That total is the matching \(t\). (If some point within that budget had a lower NLL, its penalized total would be lower too, so the penalized fit couldn't have been the best.)
  • Going the other way, the price that matches a budget \(t\) is how much NLL one more unit of budget would buy.
  • As \(\lambda\) rises from 0, the matching \(t\) shrinks from the size of the MLE toward 0. In practice we tune \(\lambda\) (usually by cross-validation); \(t\) pictures how much the fit ended up spending.

Two price schedules.

  • Lasso: a flat price. Each unit of \(|\beta_j|\) costs \(\lambda\), starting with the first.
  • Ridge: a rising price. Size costs \(\lambda\beta_j^2\), so the next unit costs \(2\lambda\beta_j\): almost nothing near 0, more the more you've already bought.

One coefficient. Take \(\text{NLL}(\beta) = (\beta - 0.4)^2\), so the MLE is 0.4. Raising \(\beta\) from \(b\) lowers the NLL at a rate of \(2(0.4 - b)\) per unit: 0.8 at \(b = 0\), falling to 0 at the MLE.

  • Lasso: buy until the rate equals the price, \(2(0.4 - b) = \lambda\), so \(\hat\beta = 0.4 - \lambda/2\) (for \(\lambda < 0.8\)). At \(\lambda = 0.4\), \(\hat\beta = 0.2\).
  • Ridge: buy until the rate equals the next unit's price, \(2(0.4 - b) = 2\lambda b\), so \(\hat\beta = 0.4/(1 + \lambda)\). At \(\lambda = 1\), \(\hat\beta = 0.2\).
  • Both match a budget of \(t = 0.2\): given an allowance of 0.2 and no price, either penalty would buy the same \(\hat\beta\).

Tools for the lab

  • glmnet(X, y, family = "binomial", alpha = ): alpha = 0 is ridge, alpha = 1 (the default) is lasso.
  • For binomial counts, y = cbind(failures, successes), the reverse of glm()'s order.
  • glmnet scales the NLL by the sample size, so its \(\lambda\) isn't the \(\lambda\) in a penalty you code by hand. Compare coefficients, not \(\lambda\) values.

Cross-validation

  • Fit to 4/5 of the data, score the held-out 1/5 by its NLL, and rotate through all five folds.
  • Choose the \(\lambda\) with the best total held-out score. lambda.1se is the largest \(\lambda\) (the simplest model) whose score is within one SE of the best.
  • Each held-out fold plays the role of the new plot in the WOD.
  • Folds are random, so set a seed to reproduce them.

Bonus: elastic net

The elastic net charges both prices at once, mixed by a second tuning parameter \(\alpha\) between 0 and 1:

\[\min_\beta \; \text{NLL}(\beta) + \lambda \sum_j \Big[\alpha|\beta_j| + (1 - \alpha)\beta_j^2\Big]\]

  • \(\lambda\) sets the overall price; \(\alpha\) sets the mix. \(\alpha = 1\) is the lasso and \(\alpha = 0\) is ridge.
  • The next unit of \(|\beta_j|\) costs \(\lambda\alpha + 2\lambda(1 - \alpha)|\beta_j|\): a flat fee from the lasso part, plus a rising price from the ridge part.
  • The flat fee means a coefficient can still be exactly 0. The rising part keeps any one coefficient from getting large, so the fit spreads its spending more evenly than the lasso does.

For the one-coefficient example, buying until the NLL's rate equals the price gives

\[\hat\beta = \frac{\max(0,\; 0.4 - \lambda\alpha/2)}{1 + \lambda(1 - \alpha)}.\]

The numerator is the lasso's threshold, now reached at \(\lambda = 0.8/\alpha\); the denominator is ridge's proportional shrinkage, applied on top.

In the left panel, the purple line is the price of the next unit and the grey line is what it buys; the estimate sits where they cross, or at 0 if the first unit already costs more than it's worth. Try \(\alpha = 1\) and \(\alpha = 0\) to recover the slider above, then values in between.

In glmnet, the alpha argument is this mix. Its ridge term is written \(\frac{1 - \alpha}{2}\beta_j^2\), half of the one here, so its \(\lambda\) values won't match a hand calculation. cv.glmnet() tunes \(\lambda\) only. To choose \(\alpha\), run it at a few values of alpha with the same foldid and compare the cross-validation scores. The elastic net is a common default when there are many predictors, especially correlated ones, where the lasso and ridge behave differently; the Bd lab works through how.

Causal diagrams: which variables belong in the model?

AIC, cross-validation, and the lasso choose variables by how well they predict. When the question is what would happen if we changed something (protect big trees, close a road), the best predictive model can give the wrong answer. A causal diagram states which variables affect which, and it tells us which variables to include before any model comparison starts.

1. Prediction vs. intervention

A manager might ask where creepers are common (prediction) or what would happen to creepers if we protected big trees (a causal effect). For prediction, any variable that carries information about creeper counts is useful. A regression slope estimates a causal effect only if the model includes the right other variables, and the data alone can't tell us which those are.

A directed acyclic graph (DAG) draws each variable as a node and each direct causal effect as an arrow; "acyclic" means no chain of arrows leads back to where it started. A DAG belongs in the THEORIES box of the workflow: it is a claim about how the system works, made before fitting, and rival theories can have rival DAGs.

2. Three ways a third variable connects

Each panel asks about the effect of big trees (or, in the middle, road access) on creepers.

  • Confounder: old stands have big trees, and also other features creepers like. Leave stand age out and big trees get credit for its effect. Include it.
  • Mediator: logging near roads removes big trees. To estimate the total effect of road access, leave big trees out; including them blocks the path we want to measure.
  • Collider: big trees support more bark insects, and creepers eat them, so insect density depends on both. Leave it out; including it creates an association between big trees and creepers even if there is none.

In short: adjust for common causes of the predictor and the response, and not for consequences of either.

3. A collider fools AIC

Simulated stations where big trees have no effect on creepers, but both affect bark insects:

  0.8 * big_trees - 0.6 * as.vector(scale(creepers)) + rnorm(n_sta, sd = 0.5))

Bonus: Bayesian model comparison and shrinkage priors

This bonus part brings the same ideas to models fit by MCMC. A ridge penalty is equivalent to a Normal prior, so regularization has a direct Bayesian counterpart. WAIC and LOO estimate predictive performance from the posterior, and shrinkage priors do the job of ridge and the lasso while keeping the full posterior uncertainty.

1. Why not AIC?

AIC needs a single best-fit \(\hat\theta\) and a count of parameters. An MCMC fit gives a whole posterior instead, and priors constrain parameters to different degrees, so the parameter count is no longer clear-cut. WAIC and LOO (section 3) handle both problems.

2. Ridge is a prior

Eight survey routes each report a change in log abundance, \(y_i \sim \text{Normal}(\mu, \sigma = 0.15)\), where \(\mu\) is the regional trend.

  1. The ridge fit from Regularization, with one parameter: \[\text{PNLL}(\mu) = \sum_{i=1}^n \frac{(y_i - \mu)^2}{2\sigma^2} + \lambda \mu^2\] (the NLL is the Normal density's exponent; the \(\log\sqrt{2\pi\sigma^2}\) terms don't involve \(\mu\), so they drop out).
  2. Bayes' rule, then \(-\log\): \[P(\mu \mid y) \propto \mathcal{L}(\mu)\, P(\mu) \quad\Rightarrow\quad -\log P(\mu \mid y) = -\log \mathcal{L}(\mu) - \log P(\mu) + \text{const.}\]
  3. A skeptical prior centered on "no trend," \(\mu \sim \text{Normal}(0, \tau)\): \[-\log P(\mu) = \frac{\mu^2}{2\tau^2} + \text{const.}\]
  4. Together: \[-\log P(\mu \mid y) = \sum_{i=1}^n \frac{(y_i - \mu)^2}{2\sigma^2} + \frac{\mu^2}{2\tau^2} + \text{const.}\]
  5. This matches the ridge PNLL when \(\lambda = 1/(2\tau^2)\), so both have the same minimum: the ridge estimate is the posterior mode. A narrow prior means a big penalty; a vague prior (\(\tau \to \infty\)) gives \(\lambda \to 0\), the MLE.
  6. Setting the derivative to 0: \[\hat\mu = \bar y \cdot \frac{n}{n + \sigma^2/\tau^2}\] This is the MLE times a shrinkage factor below 1. The prior acts like \(\sigma^2/\tau^2\) extra routes that each reported exactly 0.
# 8 survey routes: change in log abundance ~ Normal(mu, sigma = 0.15); mu = regional trend
route_y <- c(0.12, -0.05, 0.20, 0.08, -0.10, 0.15, 0.02, 0.10)
sigma <- 0.15
tau <- 0.05                       # prior: mu ~ Normal(0, tau)
lambda <- 1 / (2 * tau^2)         # ridge penalty that matches it
nll_mu <- function(mu) sapply(mu, function(m) sum((route_y - m)^2) / (2 * sigma^2))
pnll_mu <- function(mu) nll_mu(mu) + lambda * mu^2                       # ridge
neg_log_post <- function(mu) nll_mu(mu) - dnorm(mu, 0, tau, log = TRUE)  # Bayes
c(MLE = mean(route_y),
  ridge = optimize(pnll_mu, c(-1, 1))$minimum,
  posterior_mode = optimize(neg_log_post, c(-1, 1))$minimum)

3. WAIC and LOO

  • Score: the expected log predictive density (elpd). For each data point, average its likelihood over the posterior draws, take the log, and sum over points. Higher is better; the "IC" versions are \(-2 \times\) elpd.
  • Penalty: effective number of parameters, estimated from the posterior.
  • DIC (Bolker 6.6.3): \(p_D\) = mean deviance minus the deviance at the posterior means.
  • WAIC: \(p_{\text{waic}}\) = the summed posterior variance of each point's log likelihood.
  • LOO: approximates refitting the model without each point (PSIS). Pareto \(k > 0.7\) flags points where the approximation fails.
  • Stan has to save log_lik[i] for every observation, in generated quantities.
library(cmdstanr)
library(loo)

# fir NegBin power law; G = 1: one a, b, k for all trees; G = 2: separate for wave/non-wave
fir_code <- "
data {
  int<lower=1> N;
  int<lower=1> G;
  array[N] int<lower=0> cones;
  vector<lower=0>[N] dbh;
  array[N] int<lower=1, upper=G> grp;
}
parameters {
  vector[G] log_a;
  vector[G] b;
  vector<lower=0>[G] k;
}
model {
  log_a ~ normal(0, 5);
  b ~ normal(0, 5);
  k ~ exponential(0.1);
  cones ~ neg_binomial_2(exp(log_a[grp]) .* pow(dbh, b[grp]), k[grp]);
}
generated quantities {
  vector[N] log_lik;    // one value per tree, for WAIC and LOO
  for (i in 1:N)
    log_lik[i] = neg_binomial_2_lpmf(cones[i] | exp(log_a[grp[i]]) * dbh[i]^b[grp[i]], k[grp[i]]);
}
"
fir_model <- cmdstan_model(write_stan_file(fir_code))
fit_fir <- function(G) {
  grp <- if (G == 1) rep(1L, nrow(fir)) else wave
  fir_model$sample(data = list(N = nrow(fir), G = G, cones = fir$TOTCONES, dbh = fir$DBH,
                               grp = grp),
                   chains = 4, parallel_chains = 4, seed = 746, refresh = 0,
                   show_messages = FALSE)
}
fit_nowave_b <- fit_fir(1)
fit_full_b <- fit_fir(2)
# DIC (Bolker 6.6.3): pD = mean deviance - deviance at posterior means; DIC = Dhat + 2 pD
dic <- function(fit, G) {
  grp <- if (G == 1) rep(1L, nrow(fir)) else wave
  d_bar <- mean(-2 * rowSums(fit$draws("log_lik", format = "matrix")))
  pm <- function(v) colMeans(fit$draws(v, format = "matrix"))
  d_hat <- -2 * sum(dnbinom(fir$TOTCONES, mu = exp(pm("log_a")[grp]) * fir$DBH^pm("b")[grp],
                            size = pm("k")[grp], log = TRUE))
  c(DIC = d_hat + 2 * (d_bar - d_hat), pD = d_bar - d_hat)
}

waic_full <- waic(fit_full_b$draws("log_lik", format = "matrix"))

4. Shrinkage priors

pois_code <- "
data {
  int<lower=1> N;

  matrix[N, K] X;
  array[N] int<lower=0> y;

  real b0;

Bayes factors and RJMCMC

  • A Bayes factor is a ratio of marginal likelihoods (the likelihood averaged over the prior). It is sensitive to vague priors and hard to compute (Bolker 6.6.3).
  • RJMCMC and spike-and-slab priors let the sampler jump between models, giving posterior model probabilities. They need discrete parameters, so they run in JAGS or NIMBLE rather than Stan.
